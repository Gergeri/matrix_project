# Сравнительный анализ методов тестирования

## 1. Цель анализа

Сравнить методы тестирования программного обеспечения,
определить их преимущества, недостатки и особенности
применения в проекте matrix_project.

## 2. Методы чёрного ящика

### Эквивалентное разбиение

Суть: входные данные разделяются на группы,
представители которых должны обрабатываться одинаково.

Преимущества:
- Уменьшает количество необходимых тестов.
- Позволяет проверять корректные и некорректные данные.

Недостатки:
- Возможен пропуск ошибок внутри одной группы.
- Не учитывает внутреннюю структуру программы.

Применение: проверка корректных и некорректных
размеров матрицы и введённых элементов.

### Анализ граничных значений

Суть: проверяются значения на границах допустимых диапазонов.

Преимущества:
- Помогает обнаруживать ошибки на границах диапазонов.
- Позволяет создавать небольшие наборы тестов.

Недостатки:
- Не выявляет все ошибки логики программы.
- Требует определения допустимых границ.

Применение: проверка нулевых и положительных
размеров матрицы.

## 3. Методы белого ящика

### Покрытие операторов

Суть: каждый исполняемый оператор должен быть
выполнен хотя бы один раз.

Преимущества:
- Позволяет определить непроверенные участки кода.
- Легко измеряется инструментами покрытия.

Недостатки:
- Не гарантирует проверку всех исходов условий.

### Покрытие решений

Суть: каждое решение должно быть проверено
для истинного и ложного результата.

Преимущества:
- Проверяет альтернативные пути выполнения.
- Помогает выявлять ошибки ветвления.

Недостатки:
- Не гарантирует проверку каждого простого
условия в составном выражении.

### Покрытие условий

Суть: каждое простое логическое условие должно
принимать значения True и False.

Преимущества:
- Позволяет подробно проверить логические выражения.
- Подходит для проверки поиска минимума и максимума.

Недостатки:
- Не гарантирует проверку всех комбинаций условий.
- Может потребовать дополнительных тестов.

### Комбинаторное покрытие условий

Суть: проверяются комбинации значений простых
условий внутри составного логического выражения.

Преимущества:
- Позволяет обнаруживать ошибки взаимодействия условий.
- Обеспечивает более подробную проверку логики.

Недостатки:
- Количество тестов быстро увеличивается.
- Некоторые комбинации могут быть недостижимы
из-за короткого замыкания логических операций.

Применение: проверка выражения
not matrix or not matrix[0].

Проверены случаи:
- Пустая матрица.
- Матрица с пустой первой строкой.
- Матрица с непустой первой строкой.

## 4. Сравнение методов

| Метод | Преимущество | Ограничение |
|---|---|---|
| Эквивалентное разбиение | Меньше тестов | Не учитывает внутреннюю логику |
| Граничные значения | Проверка границ | Не охватывает все сценарии |
| Покрытие операторов | Контроль выполнения кода | Не проверяет все исходы |
| Покрытие решений | Проверка ветвлений | Не все простые условия |
| Покрытие условий | Проверка True и False | Не все комбинации |
| Комбинаторное покрытие | Проверка сочетаний условий | Увеличение числа тестов |

## 5. Рекомендации

Для проекта matrix_project рекомендуется комбинировать
несколько методов тестирования.

Эквивалентное разбиение и граничные значения подходят
для проверки пользовательского ввода.

Покрытие решений и условий рекомендуется применять
для проверки алгоритма поиска минимального и
максимального элементов.

Комбинаторное покрытие полезно для проверки
составных логических выражений.

Автоматические тесты рекомендуется запускать
после каждого изменения программы.

## 7. Вывод

Ни один метод тестирования не гарантирует обнаружения
всех возможных ошибок.

Совместное применение методов чёрного и белого ящика
позволяет проверить как соответствие программы
ожидаемому поведению, так и внутреннюю логику.

Для небольшого проекта обработки матриц наиболее
целесообразно сочетание проверки входных данных,
покрытия условий, решений и регрессионных тестов.
